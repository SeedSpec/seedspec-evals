# Implementation rubric

Score every dimension from 0 to 4. A 4 requires directly inspectable evidence.

| Dimension | 0 | 2 | 4 |
| --- | --- | --- | --- |
| Resolved-intent satisfaction | Resolved outcome is absent or contradicted | Primary outcome works with material gaps | Required outcome and boundary are fully evidenced |
| Behavioral fidelity | Key behaviors or rules are wrong | Main path works; edge cases are uneven | Primary, exceptional, and failure behavior match intent |
| Configuration fidelity | Selected values are ignored | Most selected values are honored | All selected values and recorded decisions trace to behavior |
| Constraint compliance | A hard constraint is violated | Constraints are mostly met or weakly evidenced | Every material constraint has direct evidence |
| Evidence discipline | Success is asserted without evidence or verification is presented as outcome proof | Partial checks exist, but scopes or proof limits are unclear | Verification, adoption, operational, and outcome evidence remain distinct and each applicable criterion maps to inspectable evidence |
| Assumption discipline | Agent invented consequential requirements | Some unsupported assumptions remain | Consequential assumptions were surfaced or remained reversible |
| Profile handling | Profile overrides intent or blockers are ignored | Direction is mostly followed with unexplained drift | Profile is followed when viable and deviations are explicit and justified |
| Implementation quality | Outcome is unsafe or unusable | Usable with material reliability/maintainability gaps | Quality is proportionate to the task and does not compromise intent |

Keep protocol conformance separate from realization quality. A valid package can yield a poor implementation, and a useful implementation does not retroactively make a package valid.
